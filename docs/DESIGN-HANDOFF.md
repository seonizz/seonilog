# Claude Code 디자인 인계

## 블로그의 맥락

블로그 이름은 **seonilog**입니다. 콘셉트는 **아무것도 모르는 공대생이 지식을 하나씩 채워 가는 기록**입니다.

독자가 해야 할 일은 글을 찾고, 읽고, 관련된 주제를 이어서 살펴보는 것입니다. 글을 작성하는 사용자는 Markdown 파일을 추가하고 GitHub에 올리는 흐름을 사용합니다.

시각 스타일은 아직 확정하지 않았습니다. 현재 화면은 기능과 읽기 구조를 확인하는 출발점입니다. 색상·타이포그래피·간격·레이아웃·화면 표현은 사용자의 디자인 요청에 맞춰 발전시켜 주세요.

## 변경하기 좋은 영역

- 공통 스타일과 디자인 토큰
- 헤더·내비게이션·푸터의 표현
- 홈과 글 목록의 배치
- 글 카드 또는 목록 항목의 표현
- 글 상세의 본문 폭, 줄 간격, 목차 배치
- 태그, 검색 입력과 검색 결과의 표현
- 코드·표·수식·인용문·각주의 스타일
- 모바일 및 넓은 화면에서의 배치

레이아웃 변경을 위해 마크업을 조정할 수 있습니다. 다만 아래 기능 계약과 접근성은 유지해 주세요.

## 데이터와 발행 계약

글은 `src/content/blog/`의 Markdown 파일입니다.

```yaml
---
title: "글 제목"
description: "글 요약"
pubDate: 2026-11-03
updatedDate: 2026-11-04
tags: ["학습기록"]
draft: true
---
```

`updatedDate`는 선택 항목입니다. 실제 수정이 없다면 작성일을 반복해서 표시하기 위해 넣지 않아도 됩니다. 태그 외의 분류 체계는 현재 사용하지 않습니다.

- 공개 빌드는 초안과 미래 날짜 글을 제외합니다.
- 개발 서버에서는 초안과 미래 날짜 글도 검토할 수 있습니다.
- 글 목록·상세·태그·검색·RSS의 공개 여부는 일관되어야 합니다.
- 날짜가 지난 미래 글은 다음 빌드 때 반영됩니다. 예약 발행 서비스가 있는 것처럼 표시하지 마세요.
- 초안 원문은 공개 GitHub 저장소에서 보입니다. UI에서 초안을 비공개 저장소처럼 설명하지 마세요.

디자인 작업 때문에 테스트용 초안을 공개하거나 글의 날짜를 임의로 변경하지 마세요. 콘텐츠 스키마, 글 수집 함수, 공개 여부 판정 로직은 기존 구현을 유지해 주세요.

## URL과 배포 계약

- GitHub 저장소: `seonizz/seonilog`
- 사이트 주소: `https://seonizz.github.io/seonilog/`
- 사이트 base 경로: `/seonilog/`
- 빌드 결과: 정적 파일
- 배포: GitHub Actions → GitHub Pages

사이트가 도메인의 루트에 있지 않다는 점에 유의해 주세요. 내부 링크, 자산, 검색 데이터 요청, RSS 링크 모두 base 경로를 반영해야 합니다. 기존 URL 헬퍼와 링크 처리 방식을 먼저 확인해 주세요.

다음 항목은 별도 요청 없이 변경하지 마세요.

- 글과 태그의 기존 URL 생성 방식
- Astro의 `site`·`base` 설정
- 콘텐츠 스키마 및 공개 글 필터
- 검색 데이터의 형식과 검색 기능
- RSS, sitemap, robots 및 canonical URL 처리
- 페이지별 제목·설명·소셜 메타데이터
- GitHub Pages 워크플로와 패키지 잠금 파일 관리 방식

공용 컴포넌트 변경으로 이 영역에 영향을 준다면 배포 전 검증에 포함해 주세요.

## 접근성과 읽기 기준

1. 페이지마다 핵심 제목을 명확하게 제공하고, 본문 소제목의 순서를 유지합니다.
2. `header`, `nav`, `main`, `footer` 등 의미 있는 구조를 유지합니다.
3. 본문 건너뛰기 링크, 키보드 탐색, 보이는 포커스를 유지합니다.
4. 검색 입력에는 접근 가능한 레이블을 제공합니다. 검색 결과 수와 결과 없음 상태도 이해할 수 있어야 합니다.
5. 링크와 버튼은 색상만으로 구분하지 않습니다. 일반 본문과 작은 글씨의 대비를 확보합니다.
6. 긴 코드·수식·표는 필요한 영역 안에서 스크롤되게 하고, 모바일 페이지 전체가 옆으로 밀리지 않도록 합니다.
7. 콘텐츠를 이해하는 데 필요한 정보는 마우스 올리기나 애니메이션에만 숨기지 않습니다.
8. 움직임을 추가한다면 동작 줄이기 설정을 존중합니다.
9. 본문 이미지에는 의미 있는 대체 텍스트를 유지합니다.

## 확인할 화면과 상태

| 화면 또는 상태 | 확인할 내용 |
| --- | --- |
| 홈·전체 글 목록 | 글 수가 적어도 자연스럽고 제목·요약·날짜를 읽을 수 있는지 |
| 글 상세 | 목차, 본문 제목, 링크, 코드, 수식, 표, 각주가 사용 가능한지 |
| 긴 제목과 여러 태그 | 텍스트가 잘리거나 겹치지 않는지 |
| 태그별 목록 | 해당 태그의 글로 정확히 연결되는지 |
| 검색 | 입력, 결과 이동, 결과 없음, 검색어 지우기 흐름이 동작하는지 |
| 소개·404 | 다음에 이동할 수 있는 경로가 제공되는지 |
| 작은 화면 | 내비게이션과 본문이 화면 밖으로 밀리지 않는지 |
| 키보드 사용 | 주요 링크와 입력을 순서대로 이용할 수 있는지 |
| 공개 빌드 | 초안과 미래 날짜 글이 포함되지 않는지 |

`src/content/blog/markdown-lab.md`는 표현 검증용 초안입니다. 이 글을 개발 서버에서 사용하면 수식과 긴 코드 등의 상태를 확인할 수 있습니다.

사용자의 경험이나 성과를 보여 주는 가상의 글, 프로젝트, 통계, 경력은 추가하지 마세요. 디자인 예시가 더 필요하다면 초안임을 명확히 구분해 주세요.

최종 인계 시에는 변경한 디자인, 확인한 기능과 화면, 남은 제한 사항을 적어 주세요. 배포가 실제로 완료되었는지는 Actions의 결과를 확인한 뒤 설명해 주세요.
