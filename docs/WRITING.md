# seonilog 글 작성 안내

글은 `src/content/blog/` 안의 Markdown 파일로 관리합니다. Markdown은 제목, 목록, 링크 등을 간단한 기호로 표현하는 글 형식입니다. GitHub 웹에서 작성하거나 컴퓨터에서 편집할 수 있습니다.

## 방법 1: GitHub 웹에서 작성하기

개발 도구를 설치하지 않고 글을 올리고 싶으시면 이 방법으로 시작해 주세요.

1. [seonilog 저장소](https://github.com/seonizz/seonilog)를 엽니다.
2. `src` → `content` → `blog` 폴더로 이동합니다.
3. **Add file → Create new file**을 선택합니다.
4. 파일 이름을 `my-first-note.md`처럼 입력합니다. 영문 소문자·숫자·하이픈을 사용하면 주소를 관리하기 편합니다. 확장자 `.md`를 포함해 주세요.
5. 아래 예시를 복사한 뒤 날짜와 내용을 수정합니다.
6. 처음에는 `draft: true`로 저장하셔도 됩니다. 공개하려면 `draft: false`로 바꿔 주세요.
7. **Commit changes**를 선택하고 `첫 번째 학습 기록 추가`처럼 무엇을 바꿨는지 적습니다. 커밋은 변경 사항을 저장소의 기록으로 남기는 작업입니다.
8. 기본 브랜치에 변경 사항을 저장합니다. 별도 브랜치를 만들었다면 해당 변경 사항을 기본 브랜치에 합친 뒤 배포됩니다.
9. [Actions](https://github.com/seonizz/seonilog/actions)에서 방금 커밋에 해당하는 실행을 엽니다. 검사·빌드·배포가 완료되고 성공 표시가 나타나는지 확인합니다.
10. [블로그](https://seonizz.github.io/seonilog/)를 열어 글을 확인합니다. 배포가 끝나기 전에는 이전 내용이 보일 수 있습니다.

```md
---
title: "첫 번째 학습 기록"
description: "이번에 이해한 내용을 한 문장으로 적습니다."
pubDate: 2026-11-03
tags: ["학습기록"]
draft: true
---

## 무엇이 궁금했나요?

이번에 이해하고 싶은 질문을 적어 주세요.

## 제가 이해한 내용

처음 보는 분도 따라올 수 있도록 설명해 주세요.

## 직접 확인한 예시

짧은 코드, 계산 또는 실험 결과를 넣어 주세요.

## 아직 남은 질문

더 확인하고 싶은 내용을 남겨 주세요.

## 참고 자료

- [자료 제목](https://example.com)
```

GitHub의 Preview 화면과 실제 블로그의 표현은 다를 수 있습니다. 특히 수식, 코드 강조, 목차는 블로그에서 다시 확인해 주세요.

## 방법 2: 컴퓨터에서 작성하기

프로젝트 폴더에서 다음 명령을 실행합니다.

```sh
npm ci
npm run new:post -- my-first-note "첫 번째 학습 기록"
npm run dev
```

새 글은 기본적으로 `draft: true`인 초안으로 생성됩니다. `src/content/blog/my-first-note.md`를 편집한 뒤 터미널에 표시된 개발 서버 주소에서 확인해 주세요. 주소에 `/seonilog/`가 포함되는지 확인하시면 됩니다.

글 파일과 함께 사용한 이미지도 커밋하고 GitHub에 올려 주세요. 기본 브랜치에 반영되면 자동 배포가 실행됩니다.

## 글 맨 위의 설정 읽기

위아래 `---` 사이를 frontmatter라고 부릅니다. 본문과 별개로 제목·날짜 등을 지정하는 영역입니다.

| 항목 | 작성 방법 |
| --- | --- |
| `title` | 글 제목입니다. 따옴표로 감싸 주세요. |
| `description` | 목록, 검색, 공유에서 사용할 요약입니다. 내용을 구체적으로 240자 이내의 한 문장으로 적어 주세요. |
| `pubDate` | 처음 공개할 날짜입니다. `2026-11-03`처럼 적어 주세요. |
| `updatedDate` | 선택 항목입니다. 공개 후 내용을 실제로 수정했다면 수정 날짜를 적어 주세요. `pubDate`보다 이전 날짜는 사용할 수 없습니다. |
| `tags` | `["수학", "학습기록"]`처럼 적습니다. 아직 정하지 않았다면 `[]`로 둘 수 있습니다. |
| `draft` | `true`면 초안, `false`면 공개 대상입니다. 생략한 글은 기본적으로 초안으로 취급합니다. |

태그 이름을 일정하게 사용해 주세요. 태그 하나는 최대 40자이며 `C/C++`, `C#` 같은 이름도 쓸 수 있습니다. `프로그래밍`, `수학`, `공학기초`, `학습기록` 등이 출발점이 될 수 있지만, 글과 관련 없는 태그를 모두 붙일 필요는 없습니다.

## 초안과 공개 글의 차이

개발 서버에서는 초안과 미래 날짜 글도 볼 수 있습니다. 공개용 빌드는 다음 두 조건을 모두 만족한 글만 포함합니다.

- `draft: false`입니다.
- `pubDate`가 아직 오지 않은 미래 날짜가 아닙니다.

이 기준은 글 페이지뿐 아니라 공개 목록, 검색 및 피드에도 적용됩니다.

**초안은 비공개 보관 기능이 아닙니다.** `seonilog` 저장소는 공개되어 있으므로 `draft: true`인 글도 GitHub에서는 파일 원문을 읽을 수 있습니다. 개인 정보나 공개하면 안 되는 메모는 저장소에 커밋하지 말아 주세요.

미래 날짜는 예약 발행 기능이 아닙니다. 날짜가 지나더라도 자동으로 사이트가 다시 만들어지지는 않습니다. 이후 커밋 등으로 다음 빌드가 실행될 때 공개 대상에 포함됩니다.

## 자주 쓰는 Markdown

글 제목은 `title`에서 자동으로 표시됩니다. 본문의 큰 소제목은 `##`부터 사용해 주세요.

````md
## 큰 소제목

### 작은 소제목

**강조할 내용**과 *기울일 내용*을 적을 수 있습니다.

- 순서 없는 목록
- 다음 항목

1. 첫 번째 단계
2. 두 번째 단계

[링크에 표시할 이름](https://example.com)

> 인용문을 적습니다.

문장 안의 짧은 코드는 `print("hello")`처럼 적습니다.

```python
for number in range(3):
    print(number)
```

| 개념 | 제가 이해한 뜻 |
| --- | --- |
| 입력 | 계산에 사용할 값 |
| 출력 | 계산을 마친 결과 |
````

수식은 문장 안에서 `$E = mc^2$`, 별도 줄에서는 다음처럼 작성할 수 있습니다.

```tex
$$
\sum_{k=1}^{n} k = \frac{n(n+1)}{2}
$$
```

각주를 사용하려면 다음처럼 작성해 주세요.

```md
본문에 보충 설명이 필요한 부분이 있습니다.[^note]

[^note]: 여기에서 보충 내용을 설명합니다.
```

여러 표현을 한꺼번에 확인하려면 `src/content/blog/markdown-lab.md`를 참고해 주세요. 이 파일은 기본적으로 초안입니다.

## 이미지 넣기

글에 포함되는 이미지는 `src/assets/`에 저장하고 Markdown에서 상대 경로로 연결하는 방식을 권장합니다. 예를 들어 `src/assets/study-note.png`가 있다면 `src/content/blog/`의 글에서는 다음처럼 적습니다.

```md
![입력과 출력의 관계를 손으로 정리한 그림](../../assets/study-note.png)
```

대체 텍스트에는 파일 이름 대신 그림이 설명하는 내용을 적어 주세요.

`public/images/`를 사용할 수도 있습니다. `public/images/study-note.png`는 다음 주소로 연결합니다.

```md
![입력과 출력의 관계를 정리한 그림](/seonilog/images/study-note.png)
```

GitHub Pages에서는 사이트가 `/seonilog/` 아래에 있으므로 `/images/study-note.png`만 적으면 잘못된 주소를 가리킬 수 있습니다. 이미지 파일도 글과 함께 저장소에 추가해 주세요.

## 공개 전 확인

- 제목과 요약이 본문을 정확하게 설명하는지 확인합니다.
- 예제 코드나 계산을 직접 확인하고 참고 자료 링크를 남깁니다.
- `draft: false`와 공개 날짜를 확인합니다.
- 이미지와 링크가 열리는지 확인합니다.
- 컴퓨터에서 작업했다면 `npm run build` 후 `npm run verify`를 실행합니다. 코드를 변경했다면 `npm run check`와 `npm test`도 확인합니다.
- 커밋 후 Actions가 성공하고 블로그에서 변경 사항이 보이는지 확인합니다.

## 글이 보이지 않을 때

1. `draft: true`로 남아 있지 않은지 확인해 주세요.
2. `pubDate`가 미래 날짜인지 확인해 주세요.
3. 변경 사항이 기본 브랜치에 저장되었는지 확인해 주세요.
4. Actions 실행이 아직 진행 중인지, 실패했는지 확인해 주세요.
5. 실패했다면 해당 실행의 오류 메시지를 확인해 주세요. frontmatter의 따옴표, 날짜, 필수 항목 누락이 원인일 수 있습니다.

이미 공개한 글의 파일 이름은 해당 글의 주소에 영향을 줄 수 있습니다. 제목만 고칠 때는 파일 이름을 유지하고 `title`을 수정해 주세요.
